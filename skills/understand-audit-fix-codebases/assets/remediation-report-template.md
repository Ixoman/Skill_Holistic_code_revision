# Remediation report

## Scope and baseline
Skill version; date; root; source report/issue; selected IDs; authorized scope; profiles;
revision/local changes or non-Git inventory; relevant baseline failures and limitations.

## Revalidation
ID | Original claim/confidence | Current evidence | Disposition | Root cause | Decision

## Causal changes and affected contracts
Cause/IDs | Files changed | Reason | Callers/consumers | Compatibility considerations

## Verification
Check | Before | After | Method | Actual result | Remaining limitation
Include valid use, failure/boundary behavior, relevant security rejection/authorization,
and downstream regression checks. Distinguish required blocked checks from optional ones.

## Counter-review
Patch assumptions challenged, evidence, legitimate behavior checked, scope of actual
independent review or self-counter-review, and issues found/resolved during verification.

## Final dispositions
ID | Resolved and verified / Implemented; validation pending / Discarded with evidence /
Duplicate of ID / Blocked | Supporting evidence and remaining work

## Operational follow-ups and final workspace state
Separately list deployments, live-data repair, credential rotation, or other operations
not performed. Record modified files, preserved prior changes, residual risks, and
report path. Do not overwrite the source report or claim unexecuted operations.
